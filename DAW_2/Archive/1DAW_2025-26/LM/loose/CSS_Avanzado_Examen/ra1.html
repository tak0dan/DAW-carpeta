1. UD1 — Codificación de la información y lenguajes de marcas

El ordenador es una máquina digital: solo entiende binario (0 y 1). Toda la información (texto, imagen, sonido, vídeo) hay que codificarla en números binarios. El gran problema histórico fue ponerse de acuerdo en CÓMO codificar, sobre todo el texto.

ConceptoExplicación
Datos de textoCaracteres legibles (letras, números, símbolos). Es el formato más versátil y portable entre sistemas.
Datos binariosTodo lo que NO es texto: imágenes, música, vídeo, Excel, programas. Necesitan un software que sepa decodificarlos.
ASCII (1967)Estándar de la ANSI. Usa 7 bits → 128 símbolos. Suficiente para el inglés (mayúsculas, minúsculas, dígitos, puntuación y control). NO incluye la ñ ni acentos.
ASCII extendido8 bits → 256 símbolos. Los 128 primeros son ASCII; los 128 siguientes, símbolos extra. Cada región tenía su tabla → caos.
ISO 8859Normalización de las tablas de 256 caracteres. 8859-1 = Europa Occidental (incluye ñ). 8859-15 = añade el símbolo del € (recomendada para Europa Occidental).
UnicodeAsigna un número único a CADA carácter de TODAS las lenguas del planeta. Los 128 primeros coinciden con ASCII (compatibilidad).
UTF-8La forma de codificar Unicode más usada en la web. Tamaño variable: 1 byte para ASCII, 2 para lenguas europeas/árabe/hebreo, 3 para chino/japonés, 4 para símbolos raros.
📖 Explicación detallada: por qué importa la codificación y los lenguajes de marcas

¿Por qué se ven símbolos raros (Ã±, Ã©) en una web? Porque el archivo se guardó en una codificación (p.ej. UTF-8) pero el navegador lo interpreta con otra (p.ej. ISO-8859-1). Por eso TODO documento de texto debe indicar su codificación. En HTML se hace con:

<meta charset="UTF-8">

En el mismo documento hay que indicar qué codificación se usó para poder interpretar correctamente los bytes. El caso más evidente son las páginas web.

¿Qué es un lenguaje de marcas? Es un sistema que añade "marcas" (etiquetas) a un documento de texto para estructurarlo y darle significado, separando el contenido de la presentación/estructura. Las marcas no se ven como tales: indican al programa cómo tratar el contenido.

Evolución histórica (importante para el examen):

  • GML → primer intento de IBM de separar contenido de formato.
  • SGML → estándar ISO, "lenguaje madre" muy potente pero complejo.
  • HTML → derivado de SGML, pensado para la web (presentación de documentos).
  • XML → derivado de SGML, simplificado, pensado para almacenar y transmitir datos (esto es la RA4-5-6).
  • XHTML → HTML reescrito con las reglas estrictas de XML.

Tipos de lenguajes de marcas: de presentación (cómo se ve, ej. los antiguos), de procedimiento (instrucciones, ej. LaTeX) y descriptivos/semánticos (describen qué ES cada parte, ej. HTML5, XML). La tendencia actual es la semántica.

📖 Explicación detallada: bucles (for, for...in, for...of, while) y forEach

🎯 Los 4 bucles de JavaScript + forEach — cuándo usar cada uno

1. for clásico for (let i = 0; i < n; i++)

Tiene TRES partes separadas por ;: inicialización (let i = 0), condición (i < n), incremento (i++). Se ejecuta mientras la condición sea true. Es el bucle más antiguo y el más flexible.

for (let i = 0; i < 5; i++) { console.log(i); // 0, 1, 2, 3, 4 }

✅ Cuándo usarlo: Cuando necesitas el índice numérico (posición) del elemento. Ideal para recorrer arrays cuando también necesitas modificar el array original o acceder a posiciones adyacentes (arr[i-1], arr[i+1]). También para contar hacia atrás (i--) o avanzar de a varios pasos (i+=2).

2. for...in for (let clave in objeto)

Recorre las claves (propiedades) de un objeto. En cada iteración, la variable toma el nombre de la propiedad (como string). Para acceder al valor se usa objeto[clave] (notación de corchetes).

const empleado = { nombre: "Luis", edad: 28, cargo: "Dev" }; for (let prop in empleado) { console.log(`${prop}: ${empleado[prop]}`); // "nombre: Luis", "edad: 28", "cargo: Dev" }

⚠️ Trampa de examen: for...in recorre también las propiedades heredadas del prototipo, no solo las propias del objeto. Si alguien añadió Array.prototype.metodo = ... o Object.prototype.algo, también aparecerán. Para filtrar solo las propiedades propias del objeto usa hasOwnProperty():

for (let prop in empleado) { if (empleado.hasOwnProperty(prop)) { console.log(prop); // solo las suyas: nombre, edad, cargo } }

✅ Cuándo usarlo: Solo con objetos planos para recorrer sus propiedades. NO lo uses con arrays por estas razones:

  • Las claves son strings ("0", "1", "2"...) en vez de números
  • Si alguien extendió el prototipo de Array, esas propiedades extra también se recorren
  • Es más lento que for, for...of o forEach
  • No garantiza el orden de iteración

Para arrays usa for...of (valores) o forEach (valores + índice).

🎯 Ejemplo típico de examen: Dado let datos = { a: 1, b: 2, c: 3 }, usa for...in para sumar los valores:

let datos = { a: 1, b: 2, c: 3 }; let suma = 0; for (let clave in datos) { suma += datos[clave]; } console.log(suma); // 6

3. for...of for (let valor of iterable) — ES6

Recorre los valores de cualquier objeto iterable (arrays, strings, Map, Set, NodeList). No da acceso al índice, solo al valor directamente.

const colores = ["rojo", "verde", "azul"]; for (let color of colores) { console.log(color); // "rojo", "verde", "azul" } // También sirve con strings: for (let letra of "Hola") { console.log(letra); // "H", "o", "l", "a" }

✅ Cuándo usarlo: Con arrays, strings, NodeList, Set, Map cuando solo te interesan los valores y NO necesitas el índice. Es más legible que for clásico. Si necesitas índice y valores, usa forEach que da ambos.

4. while while (condición) { ... }

Repite el bloque MIENTRAS la condición sea true. Si la condición es false desde el principio, el bloque NO se ejecuta nunca. Es útil cuando NO sabes cuántas iteraciones harás (depende de algo externo como el usuario o un cálculo).

let contador = 0; while (contador < 3) { console.log(contador); // 0, 1, 2 contador++; } // Ejemplo real: adivinar un número (el usuario decide cuándo parar) let intento; while (intento !== secreto) { intento = parseInt(prompt("Adivina:")); }

✅ Cuándo usarlo: Cuando el número de iteraciones NO se conoce de antemano. Por ejemplo: leer datos hasta que el usuario escriba "salir", esperar a que una condición se cumpla, o juegos con intentos. Ten cuidado con los bucles infinitos: si la condición nunca cambia, el bucle no termina y congela el navegador.

5. forEach — método de array arr.forEach(callback)

No es un bucle de JavaScript, sino un método que todos los arrays tienen. Recibe una función (callback) y la ejecuta una vez por cada elemento. La función puede recibir hasta 3 parámetros: (elemento, índice, arrayCompleto). Devuelve undefined (no se puede encadenar).

const frutas = ["manzana", "pera", "platano"]; // Solo el elemento frutas.forEach(f => console.log(f)); // Elemento + índice frutas.forEach((f, i) => console.log(`${i}: ${f}`)); // "0: manzana", "1: pera", "2: platano" // Modificar el DOM con forEach document.querySelectorAll("li").forEach((el, i) => { el.style.color = i === 0 ? "red" : "blue"; });

⚠️ forEach NO es un bucle, es un método funcional. No puedes usar break ni continue dentro de forEach (para eso usa for...of o for clásico).

✅ Cuándo usarlo: Cuando quieras ejecutar algo por cada elemento sin crear un nuevo array. Ideal para modificar el DOM, hacer console.log, o efectos secundarios. Si necesitas devolver un nuevo array transformado, usa map(); si necesitas filtrar, usa filter().

📖 Explicación detallada: tipos de funciones en JavaScript

1. Función declarada (function declaration)

Se define con function + nombre. Tiene hoisting: puede llamarse antes de donde se define.

function sumar(a, b) { return a + b; } console.log(sumar(3, 4)); // 7

✅ Cuándo usarla: Cuando necesites una función con nombre que se use en todo el script, sin importar el orden de definición (el hoisting permite llamarla antes). Ideal para funciones principales o reutilizables.

2. Función anónima (function expression)

Se asigna a una variable. NO tiene nombre, NO tiene hoisting. No puede llamarse antes de la definición.

const multiplicar = function(a, b) { return a * b; }; console.log(multiplicar(3, 4)); // 12

✅ Cuándo usarla: Cuando quieras asignar una función a una variable condicionalmente (ej: dentro de un if), o pasarla como callback a otra función. Al no tener hoisting, el código es más predecible.

3. Función flecha (arrow function) — ES6

Sintaxis más corta: (params) => expresion. No tiene su propio this. Si un solo parámetro, se omiten paréntesis. Si una sola expresión, se omite return y {}.

const dividir = (a, b) => a / b; const cuadrado = x => x * x; console.log(dividir(10, 2)); // 5 console.log(cuadrado(4)); // 16

✅ Cuándo usarla: Es la forma moderna y más usada. Perfecta para callbacks (map, filter, forEach, eventos), funciones cortas, y cuando necesitas heredar el this del contexto padre. NO uses flecha si necesitas tu propio this (ej: métodos de objeto, constructores).

4. Parámetros por defecto — ES6

Los parámetros pueden tener valor por defecto. Si no se pasa el argumento, se usa ese valor.

function usuario(nombre, edad = 25, pais = "España") { console.log(`${nombre}, ${edad}, ${pais}`); } usuario("Ana"); // Ana, 25, España usuario("Carlos", 30); // Carlos, 30, España

✅ Cuándo usarlos: Cuando una función tiene parámetros opcionales con valores típicos. Evita tener que comprobar if (param === undefined) manualmente. Útil en configuraciones, opciones por defecto, y valores que casi siempre son iguales.

Ámbito (scope)

3. UD6.2 — DOM, métodos de array y eventos

El DOM (Document Object Model) es la representación en forma de árbol de la página HTML. JavaScript usa el DOM para seleccionar, leer, modificar, crear y eliminar elementos, y para reaccionar a eventos (clic, teclado, ratón…).

Métodos funcionales de array (muy preguntados)

Estos métodos son funciones de orden superior: reciben un callback (otra función) y operan sobre cada elemento. La clave es entender QUÉ devuelve cada uno y para QUÉ sirve en la vida real.

map() transforma

Recorre el array original y crea uno nuevo aplicando una transformación a cada elemento. No modifica el original.

[1, 2, 3] ⟶ [2, 4, 6]
// Doblar cada número
const nums = [1, 2, 3];
const dobles = nums.map(n => n * 2);
// dobles → [2, 4, 6]
✅ Usa map cuando quieras transformar todos los elementos (ej: precios +IVA, nombres en mayúsculas, array de objetos → array de strings)
filter() selecciona

Recorre el array y crea uno nuevo SOLO con los elementos que cumplen la condición. Si ninguno cumple → array vacío.

[1, 2, 3] ⟶ [2, 3] (n > 1)
// Solo los mayores de edad
const edades = [15, 22, 18, 13, 30];
const mayores = edades.filter(e => e >= 18);
// mayores → [22, 18, 30]
✅ Usa filter para quedarte solo con los que cumplen una condición (ej: tareas completadas, productos en stock, usuarios activos)
find() encuentra

Recorre y devuelve el PRIMER elemento que cumple la condición. Si ninguno cumple → undefined.

[1, 2, 3] ⟶ 2 (el 1º que es > 1)
// Buscar un usuario por ID
const usuarios = [
  { id: 1, nombre: "Ana" },
  { id: 2, nombre: "Luis" }
];
const usuario = usuarios.find(u => u.id === 2);
// usuario → { id: 2, nombre: "Luis" }
✅ Usa find para localizar un elemento concreto por su ID o identificador único
forEach() ejecuta

Ejecuta una función por cada elemento, pero NO devuelve nada (undefined). Solo sirve para ejecutar efectos secundarios (console.log, modificar otro array, etc.).

// Mostrar cada elemento
const frutas = ["manzana", "pera", "platano"];
frutas.forEach(f => console.log(`Me gusta la ${f}`));
// "Me gusta la manzana"
// "Me gusta la pera"
// "Me gusta la platano"
✅ Usa forEach cuando solo quieras hacer algo con cada elemento sin necesidad de un array nuevo
reduce() acumula

Recorre el array y acumula todos los valores en UN SOLO resultado. Recibe un acumulador y el elemento actual. El segundo parámetro es el valor inicial del acumulador.

[1, 2, 3] ⟶ 6 (suma total)
// Sumar todas las notas
const notas = [7, 8, 9, 6];
const total = notas.reduce((acum, nota) => acum + nota, 0);
// total → 30 (0+7+8+9+6)

// También sirve para aplanar arrays
const agrupado = [[1,2],[3,4]];
const plano = agrupado.reduce((a, b) => [...a, ...b], []);
// plano → [1,2,3,4]
✅ Usa reduce para calcular totales, promedios, agrupar datos, o convertir un array en un objeto
Set únicos

Set no es un método, es una estructura de datos que almacena valores ÚNICOS. Sirve para eliminar duplicados al instante.

[1, 1, 2, 3, 3] ⟶ [1, 2, 3]
// Eliminar duplicados de un array
const conRepes = [1, 1, 2, 3, 3, 4];
const unicos = [...new Set(conRepes)];
// unicos → [1, 2, 3, 4]

// También sirve con strings
const letras = [...new Set("cascara")];
// letras → ["c", "a", "s", "r"]
✅ Usa Set para quitar duplicados de un array o saber qué valores son únicos
Spread ... expande

El operador ... "expande" (saca los elementos) de un array u objeto. Sirve para clonar, combinar, o pasar argumentos.

// Unir dos arrays
const a = [1, 2];
const b = [3, 4];
const juntos = [...a, ...b];
// juntos → [1, 2, 3, 4]

// Clonar un objeto
const original = { x: 1, y: 2 };
const copia = { ...original, z: 3 };
// copia → { x:1, y:2, z:3 }

// Clonar array sin referencia
const clon = [...a];
✅ Usa spread para clonar, combinar arrays/objetos, o pasar arrays como argumentos a funciones
⚠️ Diferencia crítica para examen: map() y filter() devuelven un NUEVO array (no modifican el original). forEach() devuelve undefined — no lo asignes a una variable. find() devuelve el elemento o undefined. reduce() devuelve UN solo valor (número, string, objeto…). Set no es un método sino una estructura.

    📖 Explicación paso a paso — Cifrado César

    Visión general: Toma una frase y un número de paso, desplaza cada carácter del alfabeto esa cantidad de posiciones, y muestra el resultado cifrado. Los caracteres que no están en el alfabeto (espacios, signos) se conservan igual.

    1. Captura de elementos del DOM

    document.getElementById('number') captura el <input type="range"> que vale de 0 a 20. Se guarda en rangeInput. document.getElementById('number-value') captura el <span> que muestra visualmente el valor actual del range. document.getElementById('solucion') captura el <div> donde se escribirá el resultado. document.getElementById('run') captura el <a> que hace de botón "Enviar". document.getElementById('frase') captura el <input type="text">. alfabeto es un string enorme con todas las letras (mayúsculas, minúsculas, con Ñ, con tildes, números y símbolos) que define el "diccionario" del cifrado.

    2. Evento del range — mostrar valor en vivo

    rangeInput.addEventListener('input', () => { ... }) se ejecuta CADA VEZ que el usuario mueve el deslizador. rangeValue.textContent = rangeInput.value escribe el valor actual del range (un string como "7" o "15") dentro del <span>. Como value de un range input siempre es un string, se muestra textualmente en la etiqueta.

    3. Función cifrar(cadena, paso)

    Recibe cadena (la frase a cifrar, ej: "Hola") y paso (el desplazamiento, ej: 3). Dentro, declara let resultado = "", un string vacío que irá acumulando el resultado. El bucle for (let i = 0; i < cadena.length; i++) recorre cada carácter de la cadena de entrada por su índice i.

    const pos = alfabeto.indexOf(cadena[i]) busca el carácter actual (ej: "H") dentro del string alfabeto. indexOf devuelve la posición numérica (0-based) si lo encuentra, o -1 si NO está (ej: un espacio en blanco).

    Si pos === -1, el carácter no existe en el alfabeto → lo añade tal cual: resultado += cadena[i] (conserva espacios, signos de puntuación, etc.).

    Si pos !== -1, calcula la nueva posición con (pos + paso) % alfabeto.length. El operador % (módulo) es clave: si pos + paso supera la longitud del alfabeto, el módulo "da la vuelta" al principio. Ejemplo: alfabeto tiene 80 caracteres, pos es 78 y paso es 5 → 83 % 80 = 3 (vuelve a la posición 3). Luego alfabeto[...] obtiene el carácter cifrado y se concatena a resultado.

    Al final, return resultado devuelve el string cifrado completo.

    run.addEventListener("click", () => { ... }) se dispara al pulsar el enlace. function applyTranslations(lang) {
  document.querySelectorAll('[data-key]').forEach(element => {
    const key = element.dataset.key;
    if (translations[lang] && translations[lang][key]) {
      element.textContent = translations[lang][key];
    }
  });
  document.documentElement.lang = lang;
}

    📖 Explicación paso a paso — Multi-idioma con fetch + localStorage

    🎯 La idea central
    En vez de tener tres páginas HTML separadas para cada idioma, hay una sola página donde los textos cambian dinámicamente con JavaScript. Los textos de todos los idiomas viven en un fichero JSON externo.

    🧩 Las 4 piezas y cómo se conectan

    1. index.html — el esqueleto con "etiquetas"
    Cada elemento que necesita traducirse tiene un atributo data-key con un nombre clave:

    <h1 data-key="welcome_message">Bienvenido</h1>

    El texto que hay dentro (Bienvenido) es solo el valor inicial. JavaScript lo sustituirá. Los tres botones del nav (ES / EN / FR) son los que disparan el cambio.

    2. translations.json — el diccionario
    Es un objeto JSON con tres idiomas, cada uno con las mismas claves:

    "es": { "welcome_message": "¡Bienvenido a nuestra web!" }, "en": { "welcome_message": "Welcome to our website!" }, "fr": { "welcome_message": "Bienvenue sur notre site web !" }

    La clave (welcome_message) conecta el HTML con el JSON. Si el data-key del HTML y la clave del JSON coinciden, JavaScript sabe qué texto poner.

    3. language.js — la lógica, con tres funciones principales
    loadTranslations(lang) — descarga el JSON con fetch y llama a applyTranslations:

    fetch('translations.json') .then(response => response.json()) .then(data => { translations = data; // guarda TODO el JSON en memoria applyTranslations(lang); // aplica solo el idioma pedido })

    applyTranslations(lang) — recorre todos los elementos con data-key y sustituye el texto:

    document.querySelectorAll('[data-key]').forEach(element => { const key = element.dataset.key; if (translations[lang] && translations[lang][key]) { element.textContent = translations[lang][key]; } });

    setLanguage(lang) — se llama al pulsar un botón. Guarda el idioma elegido en localStorage (para que se recuerde si el usuario recarga la página) y llama a loadTranslations.

    4. localStorage — la memoria entre recargas

    localStorage.setItem('language', lang); // guarda al cambiar localStorage.getItem('language'); // recupera al cargar

    Al abrir la página, loadLanguage() mira si ya había un idioma guardado. Si lo hay, carga ese; si no, usa español por defecto.

    ⚡ El flujo completo cuando el usuario pulsa "EN"

    click botón EN → setLanguage('en') → localStorage.setItem('language', 'en') → loadTranslations('en') → fetch('translations.json') → applyTranslations('en') → busca cada [data-key] en el HTML → sustituye su .textContent con translations['en'][key]

    ⚠️ Una cosa a tener en cuenta
    El fetch necesita que el fichero se sirva desde un servidor (aunque sea local con Live Server o similar). Si abres el index.html directamente haciendo doble clic, el navegador bloquea la petición por seguridad (política CORS en ficheros locales) y las traducciones no cargan.

    💡 Flujo completo del multi-idioma: (1) HTML define elementos con data-key. (2) JS carga translations.json con fetch(). (3) Botones llaman a setLanguage() que guarda en localStorage y recarga. (4) applyTranslations() recorre todos [data-key] y cambia textContent. (5) window.onload restaura el último idioma usado.

    📖 Explicación paso a paso — JSON: objeto {} vs array []

    Visión general: El PDF UD_7.2 enseña a distinguir si un JSON empieza por { (objeto) o por [ (array), porque la forma de recorrerlo cambia: for...in para objetos, forEach/for...of para arrays.

    1. JSON que empieza por { } — objeto

    const textoJSON = '{ "nombre": "Elena", "edad": 26, ... }' es un string con formato JSON de objeto. JSON.parse(textoJSON) lo convierte a objeto JavaScript: { nombre: "Elena", edad: 26, ... }. Object.keys(usuario) devuelve un array con las claves: ["nombre", "edad", "ciudad", "activo"]. Object.values(usuario) devuelve los valores: ["Elena", 26, "Valencia", true]. for (let clave in usuario) { console.log(clave + ": " + usuario[clave]) } itera sobre las PROPIEDADES del objeto. En cada vuelta, clave es el nombre de la propiedad (string). Se accede al valor con notación de corchetes usuario[clave], necesaria cuando la clave está en una variable. No se puede usar usuario.clave porque eso buscaría una propiedad literal llamada "clave".

    2. JSON que empieza por [ ] — array

    const textoJSON = '[ { "nombre": "Ana", "nota": 8 }, ... ]' es un string JSON que contiene un array de objetos. JSON.parse(textoJSON) lo convierte a array JavaScript. Se puede recorrer de tres formas: for clásico for (let i = 0; i < alumnos.length; i++) accede por índice numérico y luego con alumnos[i].nombre (notación de punto, porque nombre es un literal conocido). forEach alumnos.forEach(alumno => { console.log(alumno.nombre) }) ejecuta un callback por cada elemento. for...of for (let alumno of alumnos) { ... } itera directamente sobre los VALORES del array (no sobre índices). Las tres formas producen el mismo resultado.

    3. Diferencia clave: for...in vs for...of

    for...in recorre las claves/propiedades (índices de array o nombres de propiedades de objeto). for...of recorre los valores de un iterable (array, string, Set, etc.). Usar for...in en un array devuelve los índices ("0", "1", "2"...) como strings, no los valores. Usarlo en un objeto es correcto.

    4. fetch + JSON — cómo tratar la respuesta

    Al recibir datos de una API con fetch(url).then(r => r.json()).then(data => { ... }), la variable data puede ser un objeto {} o un array []. Hay que inspeccionarla (console.log(data)) para decidir: si es objeto → for...in; si es array → forEach o for...of. Esta distinción es crítica.

    📖 Explicación paso a paso — Caza de errores

    Visión general: El examen de RA1 se centra en identificar errores en HTML, CSS, DOM y JSON, no en escribir código desde cero. Se presentan fragmentos con errores y hay que corregirlos. Los errores típicos se dividen en 4 categorías.

    1. Errores HTML

    Etiquetas mal cerradas/solapadas: <div><p>Texto</div></p> viola el orden LIFO (Last In, First Out). La última etiqueta abierta (<p>) debe cerrarse primero: <div><p>Texto</p></div>. Falta de atributos obligatorios: <img src="foto.jpg"> sin alt no es accesible. <a>Enlace roto</a> sin href no navega a ningún lado. Estructura HTML5 incompleta: falta <!DOCTYPE html> o <meta charset="UTF-8"> en el <head>.

    2. Errores CSS

    Falta de punto y coma: color: red font-size: 16px — sin ; entre propiedades, el navegador ignora la segunda. Olvidar punto/almohadilla: .miClase necesita ., #miId necesita #. Sin ellos, el navegador busca una etiqueta HTML con ese nombre. Propiedades mal escritas: backgrond-color (typo), display: flexbox (no existe, es flex). Unidades: width: 500 sin unidad se ignora. margin: 10 px con espacio entre número y unidad también es inválido.

    3. Errores DOM

    Error #1 (el que más suspende): script en <head> ejecuta getElementById antes de que el elemento exista en el DOM → devuelve null → TypeError. Solución: script al final del <body> o dentro de DOMContentLoaded. Typos en métodos: getElementByID (D mayúscula), querySelecor deben ser getElementById y querySelector. # en getElementById: getElementById("#id") es INCORRECTO (el # solo se usa en selectores CSS de querySelector). appendChild con string: padre.appendChild("<p>x</p>") falla porque appendChild espera un nodo DOM, no un string. Hay que usar createElement primero. camelCase en style: el.style.background-color es inválido en JS (el guión se interpreta como resta). Debe ser el.style.backgroundColor.

    4. Errores JSON

    Claves sin comillas dobles: {nombre: "Ana"} → las claves deben ir con comillas dobles: {"nombre": "Ana"}. Comillas simples: {"nombre": 'Ana'} → solo se permiten comillas dobles. Coma final (trailing comma): {"a":1, "b":2,} → la coma tras el último elemento es inválida. undefined/funciones: {"x": undefined} → undefined no es un valor JSON válido; usar null. Números con comillas: {"edad": "25"} → si es un número, no debe llevar comillas.
