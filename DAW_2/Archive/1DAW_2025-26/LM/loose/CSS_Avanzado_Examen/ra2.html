1. UD4.1 — HTML5 Semántico

HTML5 introdujo etiquetas semánticas que describen el significado del contenido, no solo su apariencia. Esto mejora la accesibilidad, el SEO y la mantenibilidad del código. Las etiquetas semánticas principales son: <header>, <footer>, <section>, <nav>, <article>, <aside>, <figure>, <figcaption> y <address>.

Etiquetas semánticas HTML5

EtiquetaUsoEjemplo
<header>Cabecera de la página o de una sección. Puede haber varios.<header><h1>Título</h1></header>
<nav>Menú de navegación principal.<nav><a href="#">Inicio</a></nav>
<main>Contenido principal de la página (único por página).<main><article>...</article></main>
<section>Agrupa contenido relacionado temáticamente. Con heading.<section><h2>Noticias</h2>...</section>
<article>Contenido independiente (post, noticia, comentario). Tiene sentido por sí mismo.<article><h2>Artículo</h2><p>...</p></article>
<aside>Contenido tangencial: barra lateral, widgets, publicidad.<aside><p>Anuncio</p></aside>
<footer>Pie de página o de sección. Copyright, enlaces legales.<footer><p>© 2025</p></footer>
<figure>Contenedor para imágenes, diagramas, fotos, etc.<figure><img src="foto.jpg"></figure>
<figcaption>Pie o leyenda de la figure.<figcaption>Foto de la playa</figcaption>
<address>Información de contacto del autor.<address>info@iesjuan.com</address>
⚠️ Diferencia clave: <section> tiene significado semántico, <div> no significa nada. Un <div> es un contenedor genérico sin valor semántico. <article> es para contenido que podría reutilizarse fuera del contexto de la página (como un post de un blog).
📖 Estructura completa HTML5 semántico

Estructura típica de una página HTML5:

<!DOCTYPE html> <html lang="es"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Mi Web Semántica</title> </head> <body> <header> <h1>Logo / Título</h1> <nav> <ul> <li><a href="#">Inicio</a></li> <li><a href="#">Blog</a></li> <li><a href="#">Contacto</a></li> </ul> </nav> </header> <main> <section> <h2>Últimos artículos</h2> <article> <h3>Título del artículo</h3> <p>Contenido del artículo...</p> <footer>Publicado el 10/03/2025</footer> </article> </section> <aside> <h3>Publicidad</h3> <p>Widget de anuncios...</p> </aside> </main> <footer> <p>© 2025 IES Juan de Garay</p> <address>contacto@iesjuandegaray.es</address> </footer> </body> </html>

Notas importantes:

  • Puede haber varios <header> y <footer> en una página (uno por sección).
  • <main> debe ser único por página.
  • <nav> se usa para el menú principal, no para cualquier conjunto de enlaces.
  • La declaración <!DOCTYPE html> es la forma simplificada de HTML5.
  • <meta charset="UTF-8"> es obligatorio para evitar problemas con caracteres especiales (ñ, acentos).

Elementos multimedia HTML5

3. UD4.2 — Formularios HTML5

HTML5 introdujo nuevos tipos de <input> que proporcionan validación nativa en el navegador, sin necesidad de JavaScript. También introdujo atributos como required, pattern, placeholder y pseudo-clases CSS como :valid, :invalid para feedback visual.

Tipos de input HTML5

TipoHTMLValidación nativa
Email<input type="email">Requiere formato email (user@domain)
Teléfono<input type="tel">No valida automáticamente (usar pattern)
URL<input type="url">Requiere formato URL (http://...)
Número<input type="number">Solo números, con min/max/step
Rango<input type="range">Slider con min=0 max=100 por defecto
Fecha<input type="date">Selector de fecha nativo
Color<input type="color">Selector de color nativo
Búsqueda<input type="search">Campo con diseño consistente
Contraseña<input type="password">Oculta los caracteres
Archivo<input type="file">Selector de archivos

Validación nativa HTML5

AtributoDescripciónEjemplo
requiredCampo obligatorio. No envía si está vacío.<input required>
patternExpresión regular para validar el valor.pattern="\d{9}" (9 dígitos)
min / maxValores mínimo y máximo para number/date/range.min="0" max="100"
stepIncremento permitido (number/range).step="5"
placeholderTexto de ayuda dentro del input.placeholder="Escribe aquí"
autofocusEl campo recibe el foco automáticamente.autofocus
disabledDeshabilita el campo (no se envía).disabled
readonlySolo lectura (se envía, no se edita).readonly
📖 Validación con pseudo-clases :valid :invalid

CSS para feedback visual en formularios:

/* Campo obligatorio válido → borde verde */ input:required:valid { border: 2px solid green; } /* Campo con error al hacer focus → borde rojo */ input:focus:invalid { border: 2px solid red; } /* Asterisco rojo para campos obligatorios (con class="obligatorio") */ .obligatorio:after { content: ' *'; color: red; } /* Estilo para el botón de enviar deshabilitado si hay inválidos */ input:invalid ~ button[type="submit"] { opacity: 0.5; pointer-events: none; }

Cómo funciona: Cuando el navegador valida un formulario, añade automáticamente las pseudo-clases :valid a los campos correctos y :invalid a los incorrectos. El formulario NO se envía si hay campos inválidos.

3B. Interactividad — Formularios + JavaScript

En el examen te pedirán hacer webs que hagan cosas: sumar números, validar formularios, mostrar/ocultar elementos, cambiar estilos, etc. Aquí tienes todos los patrones que necesitas con JavaScript para conectar formularios, botones e inputs a acciones reales.

🎮 Patrón 1: Formulario que suma dos números (onsubmit + función)

+ 8
HTML + JS — Sumar dos números con formulario 
<!-- onsubmit captura el evento, event.preventDefault() evita recargar -->
<form onsubmit="sumarNumeros(event)">
  <input type="number" id="num1" value="5">
  <input type="number" id="num2" value="3">
  <button type="submit">=</button>
  <span id="resultado-suma">8</span>
</form>

<script>
function sumarNumeros(event) {
  event.preventDefault(); // ← EVITA que el formulario recargue la página
  const a = parseFloat(document.getElementById('num1').value);
  const b = parseFloat(document.getElementById('num2').value);
  const suma = a + b;
  document.getElementById('resultado-suma').textContent = suma;
}
</script>
⚠️ Clave examen: Siempre usa event.preventDefault() en el onsubmit si NO quieres que la página se recargue. Sin esto, el formulario envía los datos y la página se refresca, perdiendo todo. parseFloat() convierte string a número (o parseInt() para enteros).

🎮 Patrón 4: Formulario completo con validación JS + feedback visual

HTML + JS — Validación manual con JavaScript (no solo HTML5) 
<form onsubmit="return validarFormulario(event)">
  <input type="text" id="f-nombre" required>

  <input type="password" id="f-pass" minlength="6">

<script>
function validarFormulario(event) {
  event.preventDefault();
  let valido = true;

  const nombre = document.getElementById('f-nombre').value.trim();
  if (nombre.length < 2) {
    document.getElementById('err-nombre').textContent = '❌ Mínimo 2 caracteres';
    valido = false;
  } else {
    document.getElementById('err-nombre').textContent = '✅ Correcto';
  }

  const pass = document.getElementById('f-pass').value;
  if (pass.length < 6) {
    document.getElementById('err-pass').textContent = '❌ Mínimo 6 caracteres';
    valido = false;
  } else {
    document.getElementById('err-pass').textContent = '✅ Correcto';
  }

  if (valido) {
    alert('✅ Formulario válido. ¡Registrado!');
  }
  return false; // ← EVITA el envío real
}
</script>

/* Checkbox: onchange con this.checked (true/false) */

4. UD5.1 — Posicionamiento CSS

CSS permite posicionar elementos de distintas formas con la propiedad position. También controla la visualización (display: block, inline, inline-block, none), la visibilidad (visibility: visible, hidden) y el desbordamiento (overflow: visible, hidden, scroll, auto).

Propiedad position

ValorComportamientotop/leftHueco original
staticFlujo normal (valor por defecto)Se ignoranSí
relativeSe desplaza desde su posición originalFuncionanSí (se mantiene el hueco)
absoluteSale del flujo. Respecto al padre posicionado o la ventanaFuncionanNo
fixedFijo en la ventana. No se mueve al hacer scrollFuncionanNo
stickyHíbrido: fluye hasta que llega a un tope, luego se fijaFuncionan (top, etc.)Sí (mientras fluye)
📖 Explicación detallada: posicionamiento CSS

static: Es el valor por defecto. Los elementos se colocan en el flujo normal del documento. Las propiedades top, left, right, bottom y z-index NO tienen efecto.

relative: El elemento se desplaza respecto a su posición original con top/left/etc. El hueco original se mantiene (los demás elementos no ocupan su lugar). Es como si el elemento tuviera un "fantasma" en su sitio.

absolute: El elemento sale del flujo del documento. Se posiciona respecto al antecesor posicionado más cercano (con position ≠ static). Si no hay ninguno, respecto al <html> (la ventana). Los demás elementos ocupan su lugar como si no estuviera.

fixed: Sale del flujo como absolute, pero se posiciona respecto a la ventana del navegador y NO se mueve al hacer scroll. Muy usado para menús superiores fijos y botones "volver arriba".

Diferencia clave absolute vs fixed: absolute se mueve con el scroll (porque depende de su padre posicionado), fixed NO se mueve (siempre visible en la ventana).

Z-index y superposición de capas

z-index controla qué elemento se ve encima cuando hay superposición. Solo funciona en elementos posicionados (position ≠ static). A mayor valor, más cerca del usuario. Si dos elementos tienen el mismo z-index, el último en el HTML gana.

.capa3 { position: absolute; top: 50px; left: 50px; z-index: 3; background: red; }

/* Reglas del z-index: */
/* 1. Solo funciona con position ≠ static */
/* 2. Mayor número → más cerca del usuario */
/* 3. Si mismo z-index, el último en HTML gana */
💡 Truco examen: Para que un position:absolute se posicione respecto a un contenedor específico (y no respecto a la ventana), el contenedor debe tener position:relative. Esto es el "truco del padre posicionado".
CSS — Todos los tipos de position con ejemplo visual 
/* ========== POSITION: cada tipo explicado ========== */

/* 1. static (valor por defecto) — flujo normal, top/left se ignoran */
.static { position: static; }

/* 2. relative — se desplaza, el HUECO ORIGINAL se mantiene */
.relative { position: relative; top: 20px; left: 20px; }
/* Los demás elementos NO ocupan su lugar, el hueco queda vacío */

/* 3. absolute — sale del flujo, respecto al padre posicionado más cercano */
.absolute { position: absolute; top: 0; right: 0; }
/* Si ningún padre tiene position ≠ static, respecto a <html> (ventana) */

/* 4. fixed — fijo en la ventana, NO se mueve con scroll */
.fixed { position: fixed; top: 0; width: 100%; z-index: 1000; }

/* 5. sticky — híbrido: fluye hasta que llega a un tope y se fija */
.sticky { position: sticky; top: 60px; }

/* ========== DISPLAY vs VISIBILITY ========== */
.oculto-sin-hueco { display: none; }    /* desaparece, no deja espacio */
.oculto-con-hueco { visibility: hidden; } /* invisible pero el hueco se mantiene */

/* ========== OVERFLOW ========== */
.scroll { overflow: auto; height: 100px; } /* barra si desborda */
.sin-scroll { overflow: hidden; }          /* recorta lo que desborda */

/* ========== FLOAT ========== */
.img-izquierda { float: left; margin: 0 10px 10px 0; }
.limpiar-float { clear: both; } /* elemento debajo de los floats */
⚠️ Diferencia examen: display:none vs visibility:hidden. El primero elimina la caja por completo (los demás ocupan su lugar), el segundo la oculta pero mantiene el espacio vacío. Ambos son distintos a opacity:0 que oculta visualmente pero el elemento sigue ocupando espacio y respondiendo a eventos.

5. UD5.1 — Práctica de posicionamiento

Ejercicio práctico de 7 pasos que combina todos los conceptos de posicionamiento CSS. El objetivo es crear una página con menú fixed, capas flotantes, ocultación con JavaScript, capa absolute (trampa examen), overflow, footer con clear y responsive @media.

Los 7 pasos del ejercicio

  1. Menú fixed superior — position:fixed; top:0; width:100%; z-index:100. Enlaces con hover azul/naranja.
  2. Capa con display:none — Botón que oculta la capa sin dejar hueco.
  3. Capa con visibility:hidden — Botón que oculta la capa pero mantiene el hueco.
  4. Capa "trampa" con absolute — Capa idéntica al menú pero con position:absolute en lugar de fixed (se mueve con scroll).
  5. Overflow — Contenedor con overflow auto/hidden/scroll para controlar contenido desbordado.
  6. Footer con clear:both — El pie debe estar debajo de todas las capas flotantes.
  7. @media responsive — A 600px las capas flotantes pasan a float:none y width:100%.

6. UD5.1B — Float Extra (8 pasos)

Ejercicio completo Float Extra: Crear una web que integra menú fixed, efecto parallax, aviso de cookies, float de imágenes, menú lateral flotante, clear, hover y responsive. Son 8 pasos progresivos.

Los 8 pasos

  1. Menú fixed superior — Barra de navegación fija con z-index alto.
  2. Fondo fijo parallax — background-attachment: fixed para crear efecto parallax.
  3. Aviso de cookies — Capa que desaparece con display:none al hacer clic en Aceptar.
  4. Float de imágenes — Imágenes con float: left, texto fluye alrededor.
  5. Menú lateral flotante — Barra lateral con float: right.
  6. Clear ambos lados — clear: both en el footer para que quede debajo de todo.
  7. Hover efectos — :hover en imágenes y botones (opacidad, zoom, color).
  8. @media responsive — Ajustar floats a 100% en móvil.
