1. Estructura de XML

XML (eXtensible Markup Language) es un lenguaje de marcas diseñado para almacenar y transportar datos. A diferencia de HTML, XML no define cómo se ve el contenido, sino qué es cada cosa. Es el formato estándar para intercambio de datos entre sistemas heterogéneos.

ElementoExplicaciónEjemplo
Declaración XMLPrimera línea del documento. Indica versión y codificación.<?xml version="1.0" encoding="UTF-8"?>
Elemento raízTodo documento XML debe tener UN solo elemento raíz que contiene todo<biblioteca>...</biblioteca>
EtiquetasSe abren y cierran. Diferencia mayúsculas/minúsculas.<libro></libro>
AtributosValores dentro de la etiqueta de apertura. Van entre comillas.<libro id="1">
ContenidoTexto entre etiquetas de apertura y cierre<titulo>El Quijote</titulo>
ComentariosNo se procesan, solo documentan<!-- esto es un comentario -->
CDATATexto que no debe ser parseado como XML<![CDATA[ texto con < > & ]]>
Entidades predefinidasCaracteres especiales: &lt; (<), &gt; (>), &amp; (&), &quot; ("), &apos; (')<texto>5 &lt; 10</texto>
📖 Explicación detallada: XML bien formado vs válido

XML bien formado (well-formed): Un documento XML está bien formado si cumple estas reglas sintácticas:

  • Tiene una declaración XML <?xml version="1.0"?>
  • Tiene un único elemento raíz
  • Todas las etiquetas se cierran correctamente
  • Las etiquetas están correctamente anidadas (no se cruzan)
  • Los atributos van entre comillas (simples o dobles)
  • Diferencia mayúsculas/minúsculas (<Libro> ≠ <libro>)

XML válido (valid): Un documento es válido si, además de estar bien formado, cumple con una DTD o Schema que define la estructura permitida (qué elementos pueden aparecer, en qué orden, qué atributos tienen, etc.).

<?xml version="1.0" encoding="UTF-8"?> <!-- Documento XML bien formado de ejemplo --> <biblioteca> <libro id="1"> <titulo>El Quijote</titulo> <autor>Miguel de Cervantes</autor> <anyo>1605</anyo> <precio moneda="EUR">29.95</precio> </libro> <libro id="2"> <titulo>La Celestina</titulo> <autor>Fernando de Rojas</autor> <anyo>1499</anyo> </libro> </biblioteca>

Ejemplos de XML mal formado (errores típicos):

<!-- Error 1: Etiquetas cruzadas (mal anidadas) --> <padre><hijo>texto</padre></hijo> <!-- Error 2: Dos elementos raíz --> <libro>...</libro> <libro>...</libro> <!-- Error 3: Atributo sin comillas --> <libro id=1> <!-- Error 4: Etiqueta sin cerrar --> <titulo>El Quijote <!-- Error 5: Case sensitive --> <Libro></libro>
⚠️ Errores típicos de examen en XML: (1) Etiquetas que se cruzan (mal anidadas). (2) Múltiples elementos raíz. (3) Atributos sin comillas. (4) No cerrar etiquetas. (5) Case-sensitive (Libro ≠ libro). (6) Usar caracteres & o < sin escaparlos con entidades.

2. Ejercicios oficiales — UD 8.1 XML

Estos son los 9 ejercicios del PDF oficial del profesor (UD_8.1_ejercicios_solucionados.pdf). Cada ejercicio incluye enunciado y solución oficial.

📝 Ejercicio 1 — Primer documento XML

Enunciado

Copia el siguiente ejemplo en un documento mediante un editor de texto sencillo (Bloc de notas, gedit). Guárdalo con extensión .XML y ábrelo con un navegador.

📖 Solución oficial
<?xml version="1.0" encoding="UTF-8"?> <nombre> <nombre_pila>Juan Martín</nombre_pila> <apellidos>Fernández Moreno de la Vega</apellidos> </nombre>

Este ejercicio no tiene ningún misterio. Es el XML más básico: declaración, elemento raíz, elementos hijo y contenido textual.

📖 Explicación paso a paso

Visión general: Este documento XML representa un nombre completo de persona. La estructura es deliberadamente simple para mostrar la sintaxis básica de XML: declaración, elemento raíz, elementos hijo anidados y contenido textual.

1. Estructura del documento

El elemento raíz es <nombre>. Dentro tiene dos hijos directos: <nombre_pila> (el nombre de pila) y <apellidos> (los apellidos). No hay atributos, solo contenido textual.

2. Elementos clave

  • <nombre> — Elemento raíz obligatorio. Contiene todo el documento.
  • <nombre_pila> — Almacena el nombre de pila: "Juan Martín".
  • <apellidos> — Almacena los apellidos: "Fernández Moreno de la Vega".

Jerarquía: nombre → [nombre_pila, apellidos]

3. Validación / DTD

No hay DTD explícita. El documento está bien formado: tiene declaración XML, un único elemento raíz, etiquetas correctamente anidadas y cerradas, y los nombres de etiqueta distinguen mayúsculas/minúsculas (todo en minúsculas, consistente).

📝 Ejercicio 2 — Pedido

Enunciado

Crea un documento XML para el siguiente texto, marcando los campos: destinatario del pedido, artículo pedido, dirección de entrega, fecha de entrega.

Pedido para el señor Juan Delgado Martínez. El pedido se compone de una bicicleta A2023. A entregar en la calle Barco 4, tercer piso, letra A, el día 19-5-2000.
📖 Solución oficial
<?xml version="1.0" encoding="UTF-8"?> <pedido> <destinatario>Juan Delgado Martínez</destinatario> <articulo>bicicleta A2023</articulo> <direccion>C/ Barco 4, tercer piso, letra A</direccion> <fecha>19-5-2000</fecha> </pedido>

Variante válida propuesta en clase:

<direccion> <calle>Barco</calle> <numero>4</numero> <piso>tercero, letra A</piso> </direccion>
📖 Explicación paso a paso

Visión general: El XML modela un pedido comercial con los datos esenciales: a quién va dirigido, qué artículo se pide, dónde entregarlo y la fecha de entrega. Se incluye una variante que desglosa la dirección en sub-elementos para mayor granularidad.

1. Estructura del documento

Raíz: <pedido>. Hijos directos: <destinatario>, <articulo>, <direccion> y <fecha>. Todos son elementos hoja (solo contienen texto).

2. Elementos clave

  • <pedido> — Raíz. Representa el pedido completo.
  • <destinatario> — Nombre de la persona que recibe: "Juan Delgado Martínez". Requerido.
  • <articulo> — Producto solicitado: "bicicleta A2023". Requerido.
  • <direccion> — Dirección completa de entrega. Requerido.
  • <fecha> — Fecha de entrega: "19-5-2000". Requerido.

Jerarquía: pedido → [destinatario, articulo, direccion, fecha]

Variante: La dirección puede desglosarse en direccion → [calle, numero, piso]. Ambas formas son válidas; la elección depende de si necesitas tratar cada parte por separado.

3. Validación / DTD

No hay DTD. El documento está bien formado: única raíz, etiquetas cerradas, correcto anidamiento. Los nombres descriptivos en español son válidos en XML.

📝 Ejercicio 3 — Mensaje (estructura árbol)

Enunciado

Escribir un documento XML que represente la estructura y datos de un mensaje. Completar el contenido para que tenga 3 párrafos: "¿Hola qué tal?", "Hace mucho tiempo que no escribes. A ver si llamas y quedamos pronto.", "Un saludo."

📖 Solución oficial
<?xml version="1.0" encoding="UTF-8"?> <mensaje> <remitente> <nombre>Alfredo Reino</nombre> <email>alf@ibium.com</email> </remitente> <destinatario> <nombre>Bill Clinton</nombre> <email>president@whitehouse.gov</email> </destinatario> <asunto>Hola Bill</asunto> <texto> <parrafo>¿Hola qué tal?</parrafo> <parrafo>Hace mucho tiempo que no escribes. A ver si llamas y quedamos pronto.</parrafo> <parrafo>Un saludo.</parrafo> </texto> </mensaje>

Importante: Aunque es válido poner <parrafo1>...<parrafoN>, no es útil porque no podrías recuperar todos los párrafos "de golpe" si cada etiqueta tiene un nombre distinto. Mejor usar la misma etiqueta <parrafo> para todos.

📖 Explicación paso a paso

Visión general: Este XML representa un mensaje de correo electrónico con remitente, destinatario, asunto y cuerpo. La estructura en árbol refleja los componentes típicos de un email, y el cuerpo se divide en párrafos independientes usando el mismo nombre de etiqueta.

1. Estructura del documento

Raíz: <mensaje>. Tiene cuatro ramas principales: <remitente>, <destinatario>, <asunto> y <texto>. Tanto remitente como destinatario se componen de nombre + email. La etiqueta <texto> contiene múltiples ocurrencias de <parrafo>.

2. Elementos clave

  • <mensaje> — Raíz del documento.
  • <remitente> — Contenedor con nombre ("Alfredo Reino") y email ("alf@ibium.com").
  • <destinatario> — Misma estructura: nombre ("Bill Clinton") y email ("president@whitehouse.gov").
  • <asunto> — Línea de asunto: "Hola Bill".
  • <texto> — Contenedor del cuerpo del mensaje. Hijo: <parrafo> (se repite 3 veces).

Jerarquía: mensaje → [remitente → [nombre, email], destinatario → [nombre, email], asunto, texto → [parrafo, parrafo, parrafo]]

3. Validación / DTD

No hay DTD. La clave pedagógica es entender por qué NO se deben usar nombres distintos (parrafo1, parrafo2, parrafo3): al recorrer el árbol con un parser, todos los <parrafo> se obtienen con una sola consulta, mientras que nombres distintos obligarían a consultar uno por uno. El documento está bien formado.

📝 Ejercicio 4 — Carta de desayunos

Enunciado

Representar la estructura en árbol y escribir un XML con la carta del menú de desayunos de un restaurante. Incluye desayunos con nombre, precio, descripción y calorías.

📖 Solución oficial
<?xml version="1.0" encoding="UTF-8"?> <cartadesayunos> <desayuno> <nombre>Gofres Belgas</nombre> <precio>5.95</precio> <descripcion>Dos de nuestros famosos Gofres belgas con abundante sirope</descripcion> <calorias>650</calorias> </desayuno> <desayuno> <nombre>Gobres Belgas con fresas</nombre> <precio>7.95</precio> <descripcion>Ligeros gofres belgas cubiertos de fresas y nata montada</descripcion> <calorias>900</calorias> </desayuno> <desayuno> <nombre>Gofres Belgas con frutas del bosque</nombre> <precio>8.95</precio> <descripcion>Ligeros gofres belgas cubiertos con frutas del bosque y nata montada</descripcion> <calorias>900</calorias> </desayuno> <desayuno> <nombre>Tostada Francesa</nombre> <precio>4.50</precio> <descripcion>Dos gruesas rebanadas de nuestro pan francés</descripcion> <calorias>600</calorias> </desayuno> <desayuno> <nombre>Desayuno de la casa</nombre> <precio>6.95</precio> <descripcion>Dos huevos, bacon o salchicha, tostada y patatas fritas</descripcion> <calorias>950</calorias> </desayuno> </cartadesayunos>

Dudas surgidas en clase: (1) Si el nombre del desayuno es el padre (p.ej. <Gofres_Belgas>) cada etiqueta sería distinta y no podrías recuperar todos los desayunos fácilmente. (2) Si pones <nombre> como hermano de <precio> sin agrupar en <desayuno>, un programa no podría recuperar el precio asociado a cada nombre.

📖 Explicación paso a paso

Visión general: Un catálogo de desayunos de restaurante. Cada desayuno tiene nombre, precio, descripción y calorías. La estructura demuestra cómo agrupar datos repetitivos bajo un contenedor común (<desayuno>) para mantener la relación entre los campos.

1. Estructura del documento

Raíz: <cartadesayunos>. Contiene 5 elementos <desayuno>, todos hermanos directos. Cada <desayuno> contiene en orden: <nombre>, <precio>, <descripcion> y <calorias>.

2. Elementos clave

  • <cartadesayunos> — Raíz. Agrupa todos los desayunos.
  • <desayuno> — Contenedor por plato. Se repite 5 veces. Es el elemento que asocia los datos de un mismo desayuno.
  • <nombre> — Nombre del plato (ej: "Gofres Belgas").
  • <precio> — Precio en formato decimal (ej: "5.95").
  • <descripcion> — Descripción textual del plato.
  • <calorias> — Valor calórico en kcal (ej: "650").

Jerarquía: cartadesayunos → desayuno* → [nombre, precio, descripcion, calorias]

3. Validación / DTD

No hay DTD. La solución evita dos errores típicos: (1) usar el nombre del plato como etiqueta (<Gofres_Belgas>) porque cada desayuno tendría una etiqueta distinta; (2) poner <nombre>, <precio> como hijos directos de la raíz sin agrupar, perdiendo la relación entre los campos de un mismo plato.

📝 Ejercicio 5 — ¿Están bien formados? (corregir errores)

Enunciado

Decir si los siguientes documentos XML están bien formados. Si no lo están, decir por qué y corregir los errores.

Documento 1:

<?xml version="1.0"?> <documento> <p>Mi Primer <destacar importancia=1>documento XML</destacar></p] <p>Comienza con la etiqueta <documento></p> <p>A continuacion colocamos un elemento sin contenido</p> <imagen fichero="imagen.gif"> </documento>

Documento 2:

<?xml version="1.0"?> <libros> <libro id="quijote"> <titulo>El Quijote</titulo> <autor nombre=cervantes nombre=cervantes> <descripcion>Es el m<ejor libro de cervantes.</descripcion> </libro] </Libros>
📖 Solución oficial — Errores y correcciones

Documento 1 — Errores:

  1. <p>...</p] → la etiqueta de cierre está mal (</p] en vez de </p>).
  2. importancia=1 → el atributo necesita comillas: importancia="1".
  3. <p>Comienza con la etiqueta <documento> → el carácter < se interpreta como inicio de etiqueta. Debe escaparse: &lt;documento&gt;.
  4. <imagen fichero="imagen.gif"> → etiqueta sin cerrar: debe ser <imagen fichero="imagen.gif"></imagen> o <imagen fichero="imagen.gif"/>.

Documento 1 — Solución corregida:

<?xml version="1.0"?> <documento> <p>Mi Primer <destacar importancia="1">documento XML</destacar></p> <p>Comienza con la etiqueta &lt;documento&gt;</p> <p>A continuacion colocamos un elemento sin contenido</p> <imagen fichero="imagen.gif"></imagen> </documento>

Documento 2 — Errores:

  1. </libro] → la etiqueta debe cerrarse con >, no con ].
  2. <autor nombre=cervantes nombre=cervantes> → atributo sin comillas y repetido. Corregir: <autor nombre="cervantes"></autor> o usar elementos anidados para múltiples autores.
  3. m<ejor → la < se interpreta como etiqueta. Corregir: escribir "mejor" sin <.
  4. </Libros> → case-sensitive: debe ser </libros> en minúsculas.

Documento 2 — Solución corregida:

<?xml version="1.0"?> <libros> <libro id="quijote"> <titulo>El Quijote</titulo> <autor nombre="cervantes"></autor> <descripcion>Es el mejor libro de cervantes.</descripcion> </libro> </libros>
📖 Explicación paso a paso

Visión general: Este ejercicio presenta dos documentos XML con errores sintácticos. El objetivo es identificar cada infracción de las reglas de "bien formado" y corregirla. Es el ejercicio más formativo para interiorizar la sintaxis XML.

Documento 1 — Estructura

Raíz: <documento>. Hijos: tres <p> y un <imagen>. Hay 4 errores:

  1. Cierre incorrecto: </p] usa ] en vez de >. Toda etiqueta de cierre debe terminar con >.
  2. Atributo sin comillas: importancia=1 debe ser importancia="1". Los valores de atributos siempre van entre comillas.
  3. Carácter < sin escapar: <documento> en el texto se interpreta como nueva etiqueta. Debe ser &lt;documento&gt;.
  4. Etiqueta sin cerrar: <imagen> no tiene cierre. Solución: <imagen /> o <imagen></imagen>.

Documento 2 — Estructura

Raíz: <libros>. Hijo: <libro> (con id="quijote"). Dentro: <titulo>, <autor>, <descripcion>. Hay 4 errores:

  1. Cierre incorrecto: </libro] → debe ser </libro>.
  2. Atributo repetido y sin comillas: nombre=cervantes nombre=cervantes → atributo duplicado y sin comillas. Además <autor> no tiene cierre.
  3. Carácter < en contenido: m<ejor se interpreta como etiqueta. Debe ser "mejor".
  4. Case-sensitive: </Libros> no coincide con <libros>. En XML mayúsculas y minúsculas son distintas.

Reglas que se violan:

  • Toda etiqueta abierta debe cerrarse con >.
  • Los atributos requieren comillas en su valor.
  • Los caracteres < y & en contenido textual deben escaparse con entidades.
  • XML distingue mayúsculas/minúsculas en nombres de etiqueta.

📝 Ejercicio 6 — Coches (concesionario)

Enunciado

Un concesionario envía información de vehículos en oferta: marca, modelo, motor, matrícula, kilómetros, precio original, precio oferta, extras, fotos. Crear XML con al menos 2 coches.

📖 Solución oficial
<?xml version="1.0" encoding="UTF-8"?> <oferta> <vehiculo> <marca>ford</marca> <modelo>focus</modelo> <motor>duratorc 1.4</motor> <matricula>1234AAA</matricula> <kilometros>12500</kilometros> <precio_inicial>12000</precio_inicial> <precio_oferta>10000</precio_oferta> <extra>pintura metalizada</extra> <extra>llantas</extra> <foto>11325.jpg</foto> <foto>11326.jpg</foto> </vehiculo> <vehiculo> <marca>ford</marca> <modelo>focus</modelo> <motor>duratorc 2.0</motor> <matricula>1235AAA</matricula> <kilometros>125000</kilometros> <precio_inicial>10000</precio_inicial> <precio_oferta>9000</precio_oferta> <extra>pintura metalizada</extra> <extra>spoiler trasero</extra> <extra>climatizador</extra> <foto>11327.jpg</foto> <foto>11328.jpg</foto> </vehiculo> </oferta>

Nota: los elementos <extra> y <foto> se repiten porque pueden haber múltiples valores. Así es válido y práctico.

📖 Explicación paso a paso

Visión general: Este XML modela la oferta de un concesionario de coches de segunda mano. Cada vehículo incluye datos técnicos (marca, modelo, motor, matrícula, kilómetros), precios (inicial y oferta), extras opcionales y fotos. Demuestra cómo manejar elementos repetitivos de forma correcta.

1. Estructura del documento

Raíz: <oferta>. Contiene 2 elementos <vehiculo>. Cada vehículo tiene: <marca>, <modelo>, <motor>, <matricula>, <kilometros>, <precio_inicial>, <precio_oferta>, y luego múltiples <extra> y <foto>.

2. Elementos clave

  • <oferta> — Raíz. Agrupa todos los vehículos en oferta.
  • <vehiculo> — Contenedor por coche. Se repite una vez por cada vehículo.
  • <marca> / <modelo> / <motor> — Datos de identificación del coche.
  • <matricula> — Matrícula (ej: "1234AAA").
  • <kilometros> — Kilometraje actual.
  • <precio_inicial> / <precio_oferta> — Precio original y precio rebajado.
  • <extra> — Elemento repetible. Cada ocurrencia es un equipamiento distinto.
  • <foto> — Elemento repetible. Cada ocurrencia es una imagen (nombre de archivo).

Jerarquía: oferta → vehiculo* → [marca, modelo, motor, matricula, kilometros, precio_inicial, precio_oferta, extra*, foto*]

3. Validación / DTD

No hay DTD. Es importante notar que <extra> y <foto> se repiten con el mismo nombre de etiqueta. Esto es válido y recomendable: un parser que busque "extra" encontrará todos los extras de golpe, a diferencia de usar nombres distintos (<extra1>, <extra2>).

📝 Ejercicio 7 — Árboles

Enunciado

Escribir un documento XML con información botánica sobre árboles: nombre latino, nombre común, vegetación, altura, estructura, color primavera, color otoño, resistencia heladas. Incluir: Acer monspessulanum, Olea europea, Platanus orientalis, Quercus ilex.

📖 Solución oficial
<?xml version="1.0" encoding="UTF-8"?> <ARBOLES> <ESPECIE> <n.latin>Acer monspessulanum</n.latin> <n.vulgar>Arce de Montpellier, Arce menor</n.vulgar> <hoja>Caducifolio</hoja> <altura>De 6 a 10 metro</altura> <estructura>Copa esférica. Tronco principal recto con bifurcaciones. Tronco principal irregular con bifurcaciones.</estructura> <color_prim></color_prim> <color_otonyo></color_otonyo> <resistencia></resistencia> </ESPECIE> <ESPECIE> <n.latin>Platanus orientalis</n.latin> <n.vulgar>Platano</n.vulgar> <hoja>Caducifolio</hoja> <altura>De 20 a 25 metros</altura> <estructura>Copa ovoidal. Tronco principal recto. Ramaje expandido</estructura> <color_prim>Haz verde medio, enves verde claro</color_prim> <color_otonyo>Ocre</color_otonyo> <resistencia>Heladas fuertes (hasta -20ºC)</resistencia> </ESPECIE> <ESPECIE> <n.latin>Quercus ilex</n.latin> <n.vulgar>Encina</n.vulgar> <hoja>Perenne</hoja> <altura>En torno a 25 metros</altura> <estructura>Copa esférica o elíptica irregular. Tronco principal recto. Ramaje tortuoso</estructura> <color_prim>Plateado en hojas jóvenes. En hojas antiguas, haz verde oscuro, envés plateado</color_prim> <color_otonyo></color_otonyo> <resistencia>Heladas fuertes (hasta -15ºC)</resistencia> </ESPECIE> </ARBOLES>

Detalles importantes del profesor: (1) <n.latin> incluye el punto en la etiqueta, es válido aunque inusual. (2) Incluir SIEMPRE <color_prim> y <color_otonyo> aunque estén vacíos, para mantener la estructura homogénea. (3) Evita usar la eñe o acentos en etiquetas XML, no son caracteres ASCII básicos y pueden dar problemas en XML 1.0.

📖 Explicación paso a paso

Visión general: Catálogo botánico de especies arbóreas. Cada ficha contiene nombre latino, nombre común, tipo de hoja, altura, estructura de copa, colores estacionales y resistencia a heladas. Es un ejemplo de datos científicos estructurados jerárquicamente.

1. Estructura del documento

Raíz: <ARBOLES> (mayúsculas). Contiene 4 elementos <ESPECIE>. Cada especie tiene 9 hijos: <n.latin>, <n.vulgar>, <hoja>, <altura>, <estructura>, <color_prim>, <color_otonyo>, <resistencia>.

2. Elementos clave

  • <ARBOLES> — Raíz (mayúsculas intencionadamente).
  • <ESPECIE> — Contenedor por árbol. Se repite 4 veces.
  • <n.latin> — Nombre científico en latín (ej: "Acer monspessulanum"). El punto en la etiqueta es válido aunque inusual.
  • <n.vulgar> — Nombre común o vulgar.
  • <hoja> — Tipo: "Caducifolio" o "Perenne".
  • <altura> — Rango de altura en metros.
  • <estructura> — Descripción morfológica de copa y tronco.
  • <color_prim> / <color_otonyo> — Color en primavera y otoño. Pueden estar vacíos.
  • <resistencia> — Tolerancia a heladas.

Jerarquía: ARBOLES → ESPECIE* → [n.latin, n.vulgar, hoja, altura, estructura, color_prim, color_otonyo, resistencia]

3. Validación / DTD

No hay DTD. Detalles importantes: (1) El elemento <n.latin> usa punto en el nombre — válido en XML 1.0 aunque poco común. (2) <color_prim> y <color_otonyo> se incluyen siempre aunque estén vacíos, para mantener la estructura homogénea. (3) Se evitan eñes y acentos en nombres de etiqueta por compatibilidad.

1. Estructura del documento

Raíz: <catalogo>. Contiene 2 elementos <libreria>, cada una con 3 <libro>. Las librerías se distinguen por atributos (nombre, web). Cada libro tiene hasta 8 hijos, varios con atributos propios.

2. Elementos clave

  • <catalogo> — Raíz del documento.
  • <libreria> — Contenedor por tienda. Atributos: nombre y web. Se repite 2 veces.
  • <libro> — Contenedor por título. Se repite 3 veces por librería.
  • <ISBN> — Código identificador del libro.
  • <tematica> — Tema (siempre "XML"). Atributo nivel: "Básico", "Intermedio" o "Avanzado".
  • <titulo> — Título del libro.
  • <autor> — Elemento repetible. Cada autor se marca con una etiqueta independiente.
  • <editorial> — Nombre de la editorial.
  • <fecha> — Fecha de publicación. Atributo num_edicion.
  • <web_site> — URL del libro.
  • <precio> — Precio. Atributo moneda: "euro", "dolar", "libra", etc.

Jerarquía: catalogo → libreria* → libro* → [ISBN, tematica, titulo, autor+, editorial, fecha, web_site, precio]

3. Validación / DTD

No hay DTD. La solución demuestra atributos en distintos niveles del árbol: libreria lleva nombre+web; tematica lleva nivel; fecha lleva num_edicion; precio lleva moneda. Uso correcto de elementos repetibles <autor> para múltiples autores. El mismo ISBN aparece en dos librerías distintas, lo cual es válido (un libro puede venderse en varias tiendas).

Este es el ejercicio más completo. Incluye: estructura anidada de canciones, atributos en varias jerarquías, elementos vacíos con <observaciones />, duración desglosada en minutos/segundos, y múltiples compositores por canción.

📖 Explicación paso a paso

Visión general: Colección de CDs musicales con metadatos del álbum (artista, sello, año, país, etc.) y la lista de canciones desglosada con título, compositores y duración. Es el ejercicio más rico en anidamiento y en el uso combinado de elementos y atributos.

1. Estructura del documento

Raíz: <coleccion>. Contiene 3 elementos <cd> (dos de The Beatles, uno de Rolling Stones). Cada <cd> tiene metadatos básicos y un contenedor <canciones> que a su vez contiene <contenido_cd> con las <cancion> individuales. Hay 5 niveles de profundidad.

2. Elementos clave

  • <coleccion> — Raíz. Agrupa todos los CDs.
  • <cd> — Contenedor por álbum. Contiene 10 hijos directos.
  • <artista> / <titulocd> / <sello> / <referencia> / <anyo> / <pais> / <formato> — Metadatos del disco.
  • <observaciones> — Notas adicionales. Puede ser elemento vacío: <observaciones />.
  • <genero> — Estilo musical (Rock).
  • <canciones> — Contenedor del listado. Dentro tiene <contenido_cd>.
  • <contenido_cd> — Agrupa canciones de un disco. Atributos: numero (nº de disco), opcionalmente duracion.
  • <cancion> — Una pista. Atributo numero. Contiene: <titulo>, <compositor>+ (repetible), <duracion> → [minutos, segundos].

Jerarquía: coleccion → cd* → [artista, titulocd, sello, referencia, anyo, pais, formato, observaciones, genero, canciones → contenido_cd → cancion* → [titulo, compositor+, duracion → [minutos, segundos]]]

3. Validación / DTD

No hay DTD. La solución muestra cuatro técnicas avanzadas: (1) elementos vacíos con sintaxis abreviada <observaciones />. (2) Múltiples <compositor> dentro de una canción (Jagger/Richards). (3) Duración desglosada en <minutos> y <segundos> para facilitar el procesamiento. (4) Atributos en varios niveles: numero y duracion en contenido_cd, numero en cancion.

📌 Resumen RA4-5-6: (1) XML bien formado (declaración, raíz única, etiquetas cerradas, case-sensitive, atributos entre comillas, correcto anidamiento). (2) XML válido = bien formado + cumple DTD/Schema. (3) 9 ejercicios oficiales de XML del PDF del profesor: crear catálogos, agendas, identificar errores, álbumes de fotos, pedidos, bibliotecas, discos.
