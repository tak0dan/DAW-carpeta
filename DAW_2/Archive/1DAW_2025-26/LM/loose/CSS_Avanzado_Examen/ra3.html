1. Sincronía vs Asincronía — Call Stack & Event Loop

Analogía: La sincronía es como pagar en un supermercado con un solo cajero — si el cliente de delante tarda, todos esperan. La asincronía es como pedir comida en un restaurante — pides, te sientas, y cuando está lista te avisan. JavaScript es single-threaded (un solo hilo) pero gracias al Event Loop puede manejar operaciones asíncronas sin bloquear.

🧠 Call Stack: Ejecuta código síncrono línea por línea. Task Queue: Las tareas asíncronas (setTimeout, fetch) esperan aquí. Event Loop: Cuando el stack está vacío, mueve tareas de la cola al stack.

📨 Task Queue (Cola)

JS — Sincronía vs Asincronía
// Código SÍNCRONO: se ejecuta línea por línea, en orden
console.log("1. Inicio");
console.log("2. Proceso");
console.log("3. Fin");
// → 1, 2, 3 (SIEMPRE ese orden)

// Código ASÍNCRONO: setTimeout y similares se "apartan"
console.log("A. Inicio");
setTimeout(() => console.log("B. Timeout"), 0);
console.log("C. Fin");
// → A, C, B (aunque setTimeout sea 0ms, va a la cola)
⚠️ Pregunta típica de examen: "¿setTimeout(fn, 0) se ejecuta antes que la siguiente línea?" → Falso. El código síncrono siempre se ejecuta antes que el asíncrono, aunque el timeout sea 0ms.

2. Promesas (Promise) — Estados y consumo

Analogía: Una promesa es como un ticket de hamburguesa. Cuando pides, te dan un ticket (Pending). Cuando la hamburguesa está lista (Fulfilled), te la entregan y ejecutas .then(). Si se quema la cocina (Rejected), te dan un vale de reembolso y ejecutas .catch(). Una promesa solo puede pasar de Pending a Fulfilled o Rejected — una vez resuelta, no cambia.

]);

// Promise.race - la PRIMERA en terminar gana
const ganador = await Promise.race([p1, p2]);

3. Async / Await — Código asíncrono con sintaxis síncrona

Async/Await es azúcar sintáctico sobre las promesas. async convierte cualquier función en una que devuelve una promesa. await pausa la ejecución de esa función hasta que la promesa se resuelva — sin bloquear el hilo principal. Hace que el código asíncrono se lea como si fuera síncrono.

📊 .then vs async/await Comparación lado a lado
Antes: .then()
// Anidado, menos legible
function getData() {
fetch(url)
.then(r => r.json())
.then(d => {
console.log(d);
})
.catch(e => {
console.error(e);
});
}
Ahora: async/await
// Lineal, más legible
async function getData() {
try {
const r = await fetch(url);
const d = await r.json();
console.log(d);
} catch (e) {
console.error(e);
}
}

JS — async/await con try/catch
// La función sleep: promesa que se resuelve tras ms milisegundos
function sleep(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}

// Countdown con async/await
async function countdown(segundos) {
  for (let i = segundos; i >= 0; i--) {
    document.getElementById('display').textContent = i;
    await sleep(1000); // Pausa 1 segundo sin bloquear
  }
  document.getElementById('display').textContent = "¡Tiempo!";
}

// Manejo de errores con try/catch
async function obtenerDatos() {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (err) {
    console.error("Error:", err.message);
  }
}

4. Fetch API — Llamadas HTTP a APIs REST

Fetch es la forma moderna de hacer peticiones HTTP en JavaScript. Devuelve una promesa que se resuelve con la respuesta del servidor. Importante: fetch solo lanza error si NO hay conexión de red. Un error 404 se considera "éxito" (el servidor respondió). Siempre debes verificar response.ok.

JS — Los 6 Métodos HTTP con fetch
// ============================================================
//  GET    → Obtener/leer datos   → fetch(url)
//  POST   → Crear datos nuevos   → + headers + body JSON
//  PUT    → Reemplazar completo  → mismo objeto completo
//  PATCH  → Modificar parcial    → solo los campos que cambian
//  DELETE → Borrar datos         → fetch(url, { method: 'DELETE' })
//  HEAD   → Solo cabeceras       → igual que GET pero sin body
// ============================================================

// GET — Obtener datos (por defecto)
async function obtenerUsuario(id) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return await res.json();
}

// POST — Crear datos (requiere body con JSON.stringify)
async function crearPost(titulo, contenido) {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: titulo, body: contenido, userId: 1 })
  });
  return await res.json();
}

// PUT — Reemplazar COMPLETO (envías el objeto entero aunque solo cambie un campo)
async function reemplazarPost(id, titulo, contenido) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ id, title: titulo, body: contenido, userId: 1 })
  });
  return await res.json();
}

// PATCH — Modificación PARCIAL (solo envías lo que cambia)
async function actualizarPost(id, campos) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(campos)  // ej: { title: 'Nuevo título' }
  });
  return await res.json();
}

// DELETE — Borrar datos (no necesita body)
async function borrarPost(id) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`, {
    method: 'DELETE'
  });
  if (res.ok) console.log("Borrado correctamente");
}

// HEAD — Solo cabeceras (útil para comprobar si un recurso existe)
async function comprobarExistencia(url) {
  const res = await fetch(url, { method: 'HEAD' });
  console.log(`Existe: ${res.ok} | Tipo: ${res.headers.get('Content-Type')}`);
  return res.ok;
}

🔑 Diferencia PUT vs PATCH (pregunta de examen):
PUT envía el objeto COMPLETO — si solo cambias el título, igual mandas userId, body, etc. Si falta un campo, se sobrescribe con vacío.
PATCH envía SÓLO los campos que cambian — más eficiente, sin riesgo de perder datos.
Ej: PUT = carnet entero, PATCH = solo cambiar la foto.

5. Manejo de Errores — try / catch / throw / finally

Si tu código falla (ej: JSON.parse de algo roto), el script se detiene. Con try/catch puedes "capturar" el error para que la app siga funcionando y mostrar un mensaje bonito al usuario. throw te permite lanzar tus propios errores. finally se ejecuta siempre, haya error o no.

🎯 Graceful Error Handling Formulario que falla de forma controlada
🔀 Diagrama de flujo try/catch/finally
try { código }
↙️
✅ Sin error
continúa normalmente
❌ Error
catch (e) { manejar }
⬇️
finally { limpieza } (siempre se ejecuta)
JS — Manejo de errores completo
// try/catch: captura errores para que la app no explote
try {
  const usuario = JSON.parse(jsonRoto);
  console.log(usuario.nombre);
} catch (error) {
  console.error("Error:", error.message);
  alert("Los datos vinieron corruptos.");
} finally {
  console.log("Limpieza terminada."); // Siempre se ejecuta
}

// throw: lanzar errores personalizados
function dividir(a, b) {
  if (b === 0) throw new Error("No se puede dividir por cero");
  return a / b;
}

// Error 404 en fetch NO es capturado por catch automáticamente
const res = await fetch(url);
if (!res.ok) throw new Error(`HTTP ${res.status}`); // Hay que hacerlo manual

6. Operadores Modernos — ??, ?., ??=, ||=, &&=

Nullish Coalescing (??): Solo reemplaza si es null/undefined (a diferencia de || que reemplaza cualquier valor "falso" como 0 o ""). Optional Chaining (?.): Accede a propiedades profundas sin miedo a errores si algo intermedio es null/undefined. Asignación Lógica: Atajos para asignar valores condicionalmente.

🎮 ?? vs || — Comparación interactiva
|| (OR lógico)
Haz clic en "Probar"
Falla con 0, "", false
?? (Nullish Coalescing)
Haz clic en "Probar"
Solo falla con null/undefined
🔍 Optional Chaining (?.) — Explorador de objetos anidados
JS — Operadores modernos
// ?? vs || — Diferencia clave
const altura = 0;
altura || 100;     // → 100 (¡0 es falsy!)
altura ?? 100;    // → 0 (?? solo reacciona a null/undefined)

// Optional Chaining — Acceso seguro a propiedades profundas
const usuario = { nombre: "Ana" };
usuario?.direccion?.calle;     // → undefined (no explota)
usuario?.saludar?.();          // → undefined (función opcional)

// Asignación lógica
let config = { tema: null };
config.tema ??= "oscuro";  // ??= solo asigna si es null/undefined
let contador = 0;
contador ||= 10;            // ¡Cuidado! 0 es falsy, asigna 10

7. localStorage y sessionStorage — Datos persistentes en el navegador

localStorage guarda datos de forma persistente (cierras el navegador y los datos siguen ahí). sessionStorage es volátil (al cerrar la pestaña, los datos se borran). Solo guardan texto, así que para guardar objetos hay que usar JSON.stringify y JSON.parse.

💾 Gestor de localStorage Guarda, carga y elimina datos
📦 Datos en localStorage:
JS — localStorage completo
// Guardar (solo texto)
localStorage.setItem('nombre', 'Ana');

// Recuperar
const nombre = localStorage.getItem('nombre');

// Eliminar uno
localStorage.removeItem('nombre');

// Limpiar todo
localStorage.clear();

// Guardar objetos: ¡SIEMPRE con JSON.stringify!
const carrito = [{ id: 1, producto: "Pizza" }];
localStorage.setItem('carrito', JSON.stringify(carrito));

// Recuperar objetos: ¡SIEMPRE con JSON.parse!
const datos = JSON.parse(localStorage.getItem('carrito')) ?? [];
// El ?? [] evita error si no existe la clave (getItem devuelve null)

9. Funciones — Clásica, Anónima, Flecha

Tres formas de declarar funciones en JavaScript. La clásica tiene su propio this y arguments. La anónima se asigna a una variable. La flecha (=>) es más concisa y no tiene su propio this (hereda del contexto). Todas hacen lo mismo: encapsular código reutilizable.

🎮 Tres formas de sumar Clásica vs Anónima vs Flecha
📜 Clásica
--
📝 Anónima
--
🏹 Flecha
--
JS — Los 3 tipos de funciones
// 1. Función clásica (declarada)
function sumarClasica(a, b) {
  return a + b;
}

// 2. Función anónima (expression)
const sumarAnonima = function(a, b) {
  return a + b;
};

// 3. Función flecha (arrow)
const sumarFlecha = (a, b) => a + b;

// Diferencias clave:
// - Clásica: tiene su propio 'this' y 'arguments'
// - Flecha: no tiene 'this' propio (hereda del padre)
// - Flecha: no puede usarse como constructor (new)
// - Todas pueden ser async: async function() o async () =>

⚡ Patrón ACABALO — Ejercicios del Examen real

En los PDFs del examen, muchos ejercicios vienen con /* ACABALO */ y /* FIN ACABALO */. El alumno debe COMPLETAR el código que falta. Aquí tienes los patrones más comunes con sus soluciones explicadas paso a paso.

📝 Patrón 1: addEventListener("change") — Escuchar cambios en un select
// 🔴 CÓDIGO DEL EXAMEN (viene INCOMPLETO con /* ACABALO */):
const listaOpciones = document.getElementById("opciones");
listaOpciones.addEventListener("change", function() {
  /* ACABALO */
  const seleccion = this.value;  // this = listaOpciones, .value = opción elegida
  console.log("Elegiste:", seleccion);
  // Aquí puedes llamar a una función con la selección
  if (seleccion) {
    document.getElementById("resultado").textContent = `Has elegido: ${seleccion}`;
  }
  /* FIN ACABALO */
});
// ❌ Error típico: olvidar el parámetro "change" o poner "onchange"
// ❌ Error típico: usar listaOpciones.value en lugar de this.value
// ✅ this.value devuelve el value del option seleccionado
📝 Patrón 2: descuenta() — Promesa con setTimeout (PPTLS)
// 🔴 CÓDIGO DEL EXAMEN (viene INCOMPLETO con /* ACABALO */):
// El ordenador escoge tras pasar un tiempo
function descuenta() {
  /* ACABALO */
  // 1. Crear una promesa que se resuelva después de X segundos
  const promesa = new Promise((resolve) => {
    // 2. setTimeout para esperar sin bloquear
    setTimeout(() => {
      // 3. El ordenador elige aleatoriamente
      const eleccion = opciones[Math.floor(Math.random() * opciones.length)];
      resolve(eleccion);  // Resuelve la promesa con la elección
    }, 5000);  // 5 segundos de espera
  });
  return promesa;  // 4. Devolver la promesa para poder hacer .then() o await
  /* FIN ACABALO */
}

// Llamada con .then (forma clásica):
descuenta().then(eleccion => {
  console.log("Ordenador eligió:", eleccion);
});

// O con async/await (forma moderna):
async function jugar() {
  const eleccionPC = await descuenta();
  console.log("Ordenador eligió:", eleccionPC);
}

// ✅ La promesa permite que setTimeout sea "esperable" con await
// ✅ El return de la promesa permite encadenar .then()
// ❌ Error típico: no devolver la promesa (return), entonces await no funciona
📝 Patrón 3: Promise.all — Peticiones en paralelo
// 🔴 PATRÓN TÍPICO DE EXAMEN: Varias peticiones fetch simultáneas
async function cargarTodo() {
  try {
    /* ACABALO - Promise.all lanza TODAS las fetch en paralelo */
    const [usuarios, posts] = await Promise.all([
      fetch('https://jsonplaceholder.typicode.com/users').then(r => r.json()),
      fetch('https://jsonplaceholder.typicode.com/posts').then(r => r.json())
